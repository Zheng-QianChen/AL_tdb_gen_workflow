# 计算结果、原始证据与人工修订

从 0.3.0 起，每个运行用 `record_path/results.sqlite` 保存结果。网页首页的“计算结果与修订”（`/results`）可以按配置和轮次浏览记录，查看原始分析、文件校验值和修订历史。

## 记录内容

每个端元记录总能量（eV/cell）、轮次、来源类别、当前修订版本、备注、计算分析和证据。VASP 结果分析包括可取得的 INCAR 参数、K 点设置、VASP 版本、最终能量定义、电子与离子收敛、计算是否完整结束、离子步数、CPU 时间与实际耗时。缺失的量保留为未知，不用零或“通过”代替。

INCAR、POSCAR、KPOINTS、POTCAR 和结果文件有条件地记录 SHA256。数据库保存解析结果及文件标识，不分发授权赝势。源文件应与运行目录一起备份；一个哈希不能恢复原始文件。

来源类别明确区分 VASP、外部数据、手工导入、人工示例、未经重新验证的旧格式记录以及人工修订。外部能量文件本身不能证明 VASP 收敛；计算收敛也不能单独证明最终结构身份或共同参考态兼容。

## 修改条目

在记录详情中选择“手动修订”，填写新总能量或备注，并提供修改人和修改原因。系统追加版本，保留原始记录和所有历史版本；修改能量会标记为人工修订，同时保留原来的数据来源。原始计算设置和解析证据不能通过这个表单覆盖。

修改请求必须带上读到的修订号。其他操作已经更新该记录时，保存返回冲突；重新读取和核对后才能提交，避免覆盖别人的修改。当前应用是本机工具，修改人由操作者填写，不代表经过多人身份认证。

终端操作与网页共用数据库：

```bash
python -m altdb --json results list CONFIG
python -m altdb --json results list CONFIG --iteration 0
python -m altdb --json results show CONFIG RECORD_ID
python -m altdb --json results amend CONFIG RECORD_ID --revision 0 \
  --actor "研究者" --reason "复核原始结果后更正录入值" --energy -8.25
```

`RECORD_ID` 和 `--revision` 应采用查询返回的值。初始版本为 0。

## 训练与导出

数据库是训练取数依据，`calc.txt` 作为兼容格式输出。已有数据库记录时，修改同路径 `calc.txt` 不会修改训练数据。手工数据通过 `import-results` 登记，并保留输入文件哈希和来源；旧格式数据的迁移不能伪称已重新验证 VASP 收敛。任务清单丢失时须恢复清单，不能跳过批次完整性检查。

训练保存实际消费的记录 ID、修订号和内容哈希。训练之后修改条目，不会改变已有检查点和 TDB 导出的来源快照；要让修订值参与计算，需要明确重新训练。导出的 CSV/TDB 保留实际数据来源，而不是把所有已导入数据都写成 VASP。

## 备份

备份时关闭写入服务，连同 SQLite 文件、可能存在的 WAL 文件和原始证据目录一起处理，或使用 SQLite 的在线备份 API。不要只在运行中复制主 `.sqlite` 文件。运行数据库和结果文件留在用户数据目录，不随程序包或 Git 分发。
